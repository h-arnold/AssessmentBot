# Frontend max-lines decomposition

This plan clears the 16 `max-lines` warnings reported by `npm run lint:frontend:check` by splitting each flagged file into modules with one responsibility. It also reorganises every touched cluster into a domain subfolder, because splitting creates multiple files with the same domain prefix. Deliver the whole plan as one change in three waves.

## Scope

The lint command reports 16 warnings and no errors. All 16 files exceed the 500-line warning threshold; 13 files under `src/frontend/src/**` exceed the 550-line hard trigger in `docs/developer/frontend/frontend-architecture.md`. The two E2E files are warning-only because that trigger applies to `src/**`. `assignmentsPageTestHelpers.tsx` (530 lines) is also warning-only and is handled by dead-code removal instead of splitting.

## Governing rules

- Split into coherent modules; do not shrink files by removing blank lines, joining statements, shortening names or weakening comments and documentation.
- Keep every new file below the 500-line warning threshold. The 550-line trigger applies to every touched `src/**` file being worked on, not only the one that created the excess.
- Do not add a facade or barrel solely to preserve an old import path. Update consumers to import from the owning module directly, including existing re-export blocks found during the work.
- Split tests by responsibility, with suffix names such as `X.loading.spec.tsx` and `X.save.spec.tsx`. Do not use planning labels in test or helper names (`docs/developer/frontend/frontend-testing.md`).
- Put shared test setup and fixtures under `src/test/<domain>/`. When several specs register identical mocks, use a registration-only `*.mockSetup.ts` module with typed handles, and reset with `vi.resetAllMocks()` in each spec.
- Extract a helper only for an independent contract with at least two current call sites. Extend an existing canonical helper before creating a new one (`docs/developer/frontend/frontend-shared-helpers-and-abstraction-standards.md`). A duplicated helper or duplicated test coverage is a review defect.
- Use `../x` for one-parent imports and the `@/` alias for deeper paths, as required by `import-path/path-depth`. The autofixer runs only under the fix variant (`lint:frontend`), so `:check` reports any path introduced by a move.
- The helper folders `src/test/shell/`, `src/test/referenceData/` and `src/test/settings/` are new. Create them as part of the work; `src/test/startupWarmupFixtures.ts` is a new file.
- Playwright work follows `docs/developer/frontend/frontend-playwright-e2e.md`; its shared-helper section explicitly sanctions splitting oversized specs.

```bash
npm run lint:frontend:check
npm run typecheck:all
npm run test:frontend
npm run test:frontend:coverage
npm run test:frontend:e2e
npm run regression-checker
```

`lint:frontend:check` currently exits 0 with warnings because it has no `--max-warnings 0`, so the gate requires reading the output and confirming `0 problems`. Do not change the lint configuration as part of this work. Run targeted Vitest paths during each wave; run the E2E suite after the Playwright wave. `npm run run-all-checks` is the final gate.

## Assumptions

- File and line counts come from the lint report at planning time; the lint command is the source of truth for the final set. Line ranges and budgets in the module table are estimates from the current files, not targets to meet by formatting tricks; every resulting file must be verified with `npm run lint:frontend:check`.

- The subfolder rule is applied to clusters this change touches, not to unrelated flat clusters elsewhere in the frontend.
